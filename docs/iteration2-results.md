## 2.1. Локальный каталог

`contracts/catalog.ts` отделён от React и статистического контракта. `CatalogService` работает в worker анализа; renderer получает только подготовленные страницы по 25 групп или участников. Точные группы содержат минимум два экземпляра, предупреждения хранятся отдельными парами, без транзитивного объединения.

После успешного выхода анализатора нужные записи копируются SQL-запросами из рабочей базы в `analysis/results/catalog.sqlite` до применения правила очистки 5 МиБ. Хранятся только результаты последнего завершённого анализа, максимум 128 МиБ, срок доступа 30 дней. Новая успешная запись заменяет старый каталог атомарным переименованием. При истечении срока каталог удаляется при обращении; пока приложение закрыто или каталог не запрашивается, физическая очистка не выполняется. ID нового анализа не даёт доступа к старым результатам. При ошибке сохранения UI получает `CATALOG_SAVE_FAILED`; статистический отчёт остаётся доступным. Точные временные метки сохраняются строками, чтобы не терять разряды через JavaScript Number.

Проверено: TypeScript `tsc --noEmit`; `node --test tests/catalog.test.cjs` — 2 теста успешно. Набор включает 1051 участника на двух искусственных корнях, последнюю страницу группы, singleton, цепочку похожих пар, удаление рабочей базы, повторное открытие сервиса, новый анализ, пропавшие файлы, отсутствие и истечение срока каталога, некорректные IPC-параметры. Это автоматические проверки Windows, не интерактивная проверка интерфейса и не подтверждение Linux/macOS.

API сверено с [Node SQLite](https://nodejs.org/docs/latest-v24.x/api/sqlite.html). Наличие `node:sqlite` проверено также в установленном Electron 44.7.1.

## 2.2. Экран групп и оригинал

В настоящем Electron/preload/React проверены выбор и снятие оригинала, страницы группы из 60 участников, длинные одинаковые имена в разных папках, повторное открытие окна, отсутствие каталога, Escape и восстановление фокуса. Проверены светлая/тёмная темы при 640×480, 960×640, 1280×800 и 1920×1080; снимки находятся в `.verification/results-*.png`. Каталог и файлы этого UI-набора искусственные; нативное сравнение этим тестом не подтверждается. В тесте исправлены ожидание кадра скрытого окна и моделирование фокуса кнопки перед нажатием. `tests/catalog.test.cjs` — 3 теста; полный регрессионный набор после этапа 2.1 — 133 теста успешно.

Оригинал выбирается явно и сохраняется с ID анализа. Один файл может защищаться выбором в другой группе; все такие защиты видны у участников. Новый анализ не наследует выбор. Исходные статистические счётчики не пересчитываются при изменении пользовательского решения.

## 2.3. Решения и предпросмотр

Решения «Не решено», «Оставить», «Проверить вручную», «Отмечен для удаления» и «В корзине» отделены от исходных метаданных и хешей. Последнее состояние доступно только сервису переноса, renderer не может назначить его напрямую. Само решение не изменяет файл. Похожая пара требует двух успешных предпросмотров и отдельного явного вердикта; смена оригинала сбрасывает доказательства просмотра этой пары. Оригиналы защищены также через пересекающиеся группы.

| Формат | Вид просмотра | Ограничения |
| --- | --- | --- |
| TXT, Markdown, HTML | Буквальный текст без исполнения разметки и переходов по ссылкам | Вход до 1 МиБ; UTF-8 и UTF-16 с BOM; показ до 128 КиБ UTF-8 с указанием усечения |
| DOCX | Извлечённый текст без оформления | Вход и общий объём ZIP до 8 МиБ, не более 4096 записей; отдельный XML и итоговый текст до 512 КиБ; показ до 128 КиБ |
| PNG/JPEG | Изображение после нативной проверки | Вход до 8 МиБ, до 4 194 304 пикселей, лимит памяти JPEG 64 МиБ; повреждения и неподдерживаемые варианты отклоняются |
| PDF, аудио, видео, остальные | Сообщение об отсутствии поддержки | Файл не запускается внешней программой |

Парсеры выполняются отдельным процессом, ожидание предпросмотра ограничено 15 секундами, выход — 12 МиБ. Для DOCX запрещены внешние XML-сущности; архив не извлекается на диск, активное содержимое не выполняется. Оригинал и проверяемый экземпляр показываются рядом (на узком окне последовательно), каждый со своим полным путём. Неподдерживаемый или повреждённый файл не получает отметку успешного просмотра.

Проверено: 4 теста каталога на Windows, настоящий Electron UI с имитированным нативным предпросмотром, 6 тестов настоящего нативного модуля на Linux WSL, 8 Linux CTest. Наборы включают активный HTML, UTF-16, некорректный UTF-8, усечение, лимиты входа, ZIP/XML, повреждённые PNG/JPEG, слишком большие размеры изображения, изменение/замену файла, ссылки и выход за выбранный корень.

Windows-сборка с нативным модулем от 2026-10-24 обнаружена Defender как `Trojan:Win64/Tedy.PGL!MTB`: SHA-256 `36a7d239ef7eda47cfa44302ece267d717652ba177871a6809848101f67c28fe`, движок `1.1.26090.9`, базы `1.461.179.0`, защита включена. Агент не запускал этот EXE после обнаружения. Позднее наблюдался отдельно запущенный пользовательский анализ из этого пути; он не включён в тестовый прогон. Отчёт `.verification/defender/iteration2-preview.json`. Это ограничение Windows-проверки и выпуска, а не установленная причина обнаружения; исключения и изменение PE ради вердикта не применялись.

## 2.4. Перенос в корзину

Команда принимает ID анализа, группы и от 1 до 25 уникальных ID файлов. Main получает полные пути только от каталога в worker. Настоящий системный диалог показывает удаляемые пути и сохраняемые оригиналы; первый и выбранный по умолчанию ответ — «Отмена». Для похожих пар явно указано, что содержимое может различаться. Чрезмерно длинное подтверждение отклоняется, пути не усекаются.

После подтверждения отдельно проверяются оригинал и каждый кандидат: выбранный корень, исключения сканера, приватный каталог, отсутствие ссылок и junction, тип, физический ID, размер и точные времена. Нативный процесс заново читает содержимое и рассчитывает SHA-256. Для точной группы дополнительно выполняется настоящее побайтовое сравнение; для предупреждения хеши должны совпасть с двумя ранее просмотренными экземплярами. Перед вызовом ОС main ещё раз проверяет метаданные обоих путей.

Между завершением проверки и системной операцией корзины остаётся гонка с внешним процессом: API корзины принимает путь, а не удерживаемый файловый дескриптор. Атомарная защита от злонамеренной одновременной подмены не доказана и не заявляется. Приложение проверяет доступные признаки до последнего вызова; при обнаруженном изменении прекращает операцию. Каталог пользователя не следует изменять параллельно переносу.

До обращения к ОС записывается намерение `pending`. Успех записывается только после успешного ответа ОС; сбой одного файла остаётся отдельным результатом. Повтор подтверждения локального результата не повторяет перенос. Незавершённое намерение после аварии блокирует слепой повтор и требует ручной проверки/нового анализа. Успешный перенос меняет состояние файла во всех группах, а исходные счётчики анализа остаются неизменными.

На время подтверждения, проверок и переноса заблокированы смена оригинала, решения, новый анализ, продолжение, установка обновления и завершение приложения. При отказе корзины или доступа запасного безвозвратного удаления нет.

Проверено: 7 тестов сервиса переноса и параметров подтверждения с имитированными нативными доказательствами и адаптером ОС; 4 теста каталога; 7 настоящих нативных тестов Linux, включая проверку пары и неравные байты. Windows UI-сценарий использовал настоящий Electron/preload/React и `shell.trashItem` для одного одноразового файла; оригинал остался на месте. Ответы подтверждения и нативные доказательства в этом UI-наборе имитированы. Проверены все 8 сочетаний двух тем и четырёх размеров окна. Настоящий ручной диалог через Computer Use пока не подтверждён: первый запуск остановлен пользователем Escape, в следующем наблюдались ошибки захвата кадра и геометрии свёрнутого окна.

Во время согласованной остановки пользовательского анализа окно и процессы были закрыты. Команда агента через Computer Use перед этим завершилась ошибкой геометрии. Сохранён ID `806acdad-e2a7-47dd-8606-efdee89252eb`, статус `paused`, 243401 запись, база 217686016 байт; `PRAGMA quick_check` в режиме только чтения — `ok`. Анализ автоматически не возобновлялся. Это проверка сохранности, не часть одноразовых наборов.

После освобождения EXE текущая Windows-сборка этапа 2.4 снова обнаружена Defender: SHA-256 `43040566450c9557aac1013257c3f72efee8e7e4872c847b686907daa4bd93ce`; отчёт `.verification/defender/iteration2-trash.json`. Нативный Windows-тест и выпуск остаются заблокированы, настройки защиты не менялись.

Дополнительно прошёл сквозной Linux Electron-тест `tests/results-integration.cjs`: настоящее сканирование двух искусственных корней → каталог → два предпросмотра → повторная нативная проверка и байты → настоящая системная корзина. Инъецировались только ответы пользователя на подтверждение. Оригинал сохранён, повтор уже обработанного файла отклонён, изменение похожего файла после просмотра не вызвало перенос. SHA-256 Linux-анализатора: `aa67a7099a4c052632f6c6202bd3ffa08b6a04f9b5bf2820dd07446942c9c205`; отчёт `.verification/results-integration-linux.json`.

В списке подпись «Найден» подтверждает доступность метаданных и совпадение размера, а не обещает чтение всех байтов. Содержимое и точная идентичность перепроверяются при предпросмотре и переносе. Системные ACL и отключённые накопители могут помешать этой последующей проверке.

## Дополнительная проверка Windows-адаптера

Просмотр точного [исходника Electron 44.7.1](https://github.com/electron/electron/blob/v44.7.1/shell/common/platform_util_win.cc) подтвердил, что его Windows `shell.trashItem` использует `FOFX_SHOWELEVATIONPROMPT`. Поэтому прямой вызов заменён отдельным адаптером `native/src/recycle.cpp` через проверенный worker: без флага повышения прав, с `FOF_NO_CONNECTED_ELEMENTS`, `FOFX_RECYCLEONDELETE` и veto в `PreDeleteItem`, если ОС не подтверждает возможность корзины. Смысл флагов сверялся с [Microsoft IFileOperation](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags).

Windows-адаптер повторно проверяет пару и два ранее проверенных SHA-256 перед операцией, удерживает каталоги и оригинал, перепроверяет метаданные в callback ОС. API остаётся основанным на путях, поэтому прежнее ограничение атомарности сохраняется. При потере ответа нативного процесса результат считается неопределённым, намерение `pending` не сбрасывается и слепой повтор запрещён. Тесты дополнены случаем неизвестного результата и проверкой, что папка ресурсов HTML не переносится вместе с выбранным HTML-файлом.

Сборка Windows с новым адаптером компилируется, но вновь обнаружена Defender; она не запускалась агентом. Итоговый SHA-256 `c9c15ede8c943b53e51e3cfc618ad6461f0740e953c6344ff15af7d6a436d199`, базы `1.461.181.0`, обнаружение `Trojan:Win64/Tedy.PGL!MTB`, отчёт `.verification/defender/iteration2-no-elevation-final.json`. Поэтому работа нового Windows-адаптера на реальных файлах пока не подтверждена; предыдущий UI-тест с настоящим Electron `shell.trashItem` не выдаётся за проверку этого нового адаптера. Linux/macOS используют свой системный `shell.trashItem`.

После этой правки: сборка TypeScript/Electron успешна; Linux — 146 тестов Node (144 успешно, 2 Windows-проверки пропущены), 9 нативных тестов локальных файлов успешно; настоящий сквозной анализ/предпросмотр/проверка пары/корзина и отправка фактического публичного отчёта через тестовый HTTPS также успешны. Повторный прогон настоящего Electron UI прошёл все четыре размера в обеих темах, отмену и перенос одноразового файла; снимки 640×480 и 1920×1080 дополнительно просмотрены. В тестах нового Windows-адаптера на Linux проверяется только безопасный отказ платформы; положительный Windows-сценарий не выполнен.

Для предшествующего коммита `3ddfaee` прогон [GitHub Actions 40093897944](https://github.com/frdkss/Duprove/actions/runs/40093897944) завершился успешно на Ubuntu 22.04, macOS Intel и Apple Silicon, включая UI, сквозной сценарий, упаковку и запуск пакета. Windows остановилась на проверке Defender. Эти результаты относятся к указанному коммиту, а не подменяют проверку следующей правки.

В прогоне [40096358131](https://github.com/frdkss/Duprove/actions/runs/40096358131) для `d1466e5` macOS ARM завершила все шаги успешно, Windows снова остановилась на Defender. На macOS Intel проверки итерации 2 прошли, но позднее существующий тест APFS завершился ошибкой `hdiutil detach` (16, `Resource busy`) после успешного сканирования временного образа. Тест теперь делает до 10 повторов обычного отключения с паузой 0,5 с только для кода 16; принудительное отключение и ослабление проверок не добавлены. Моделированием проверены временная занятость, исчерпание повторов и немедленный отказ для другого кода. Фактический macOS-прогон этой правки проверяется отдельно.
