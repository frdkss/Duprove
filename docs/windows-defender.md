# Проверка Windows Defender

## Установленные факты — 2026-10-15

Defender обнаруживает `Trojan:Win64/Tedy.PGL!MTB` в нативном
`duprove-analyzer.exe`, а также в некоторых тестовых EXE. События относятся
к 14–15 октября, до реализации автообновления. Это обнаружение антивируса,
а не предупреждение SmartScreen о неизвестном издателе.

Обновление баз до `1.461.41.0` не устранило обнаружение. Полная пересборка
в `.verification/defender-clean` с повторной загрузкой зависимостей также
обнаруживается. SHA-256 этой сборки:
`dad058092465b72391be1e008181612fa880446dd91c7e19e9e777535d509a0f`.
SHA-256 ранее собранного анализатора:
`b62f726ffa63a33e752e5991b08b95425d94d75341c813115227f1ee475b2bfd`.

Сканирование существующего NSIS-установщика вернуло отсутствие угроз, но
сканирование его анализатора в `release/win-unpacked/resources/analyzer`
подтвердило обнаружение: SHA-256 совпадает с ранее собранным анализатором.
Поэтому одного сканирования установщика недостаточно; проверяется и отдельный EXE.

Подписи Microsoft на компиляторе и линкере MSVC `19.51.36252.0` действительны.
Сравнение 524 файлов исходников и CMake зависимостей с повторными загрузками
не выявило различий; PicoSHA2 соответствует закреплённому коммиту, без изменений.
Архивы JSON и SQLite теперь также закреплены SHA-256 в CMake. Это проверка
целостности последующих загрузок, а не исправление антивирусной сигнатуры.

В просмотренном коде нативного анализатора нет сетевого клиента и запуска
дочерних программ. Он читает файлы, хеширует их и пишет собственную базу SQLite.
Это не полный аудит безопасности и не доказательство ложного срабатывания.
Причина классификации Defender не установлена; исправление не подтверждено.
Для проверки подготовлено обращение в Microsoft:
`.verification/defender/submission.txt`. Вложение — только
`.verification/defender-clean/bin/duprove-analyzer.exe`.
Пользователь разрешил отправку файла и описания в Microsoft 2026-10-15.
Отправка не выполнена: инструменты этой сессии не видят подключённых браузеров;
попытки открыть встроенный браузер и Chrome вернули `Browser is not available`.
Повторное разрешение на отправку этих же данных в Microsoft не требуется.

## Проверка перед упаковкой

На Windows:

```powershell
npm run check:defender
# При необходимости обновить базы и проверить конкретный файл:
npm run check:defender -- -UpdateSignatures -Path release/Duprove-1.0.0-win-x64.exe
```

Скрипт сохраняет SHA-256, версии Defender/баз, HRESULT и полный вывод сканера
в `.verification/defender/<имя файла>.json`. Код 0 означает успешную проверку;
обнаружение, недоступный Defender, базы старше 7 дней, отсутствие/изменение
файла или ошибка сканирования завершают проверку с кодом 1.

`beforePack` проверяет анализатор, включая прямой запуск electron-builder.
`npm run package` дополнительно проверяет готовый NSIS EXE. Сборка останавливается
при неуспешной проверке; ранее созданные файлы в `release/` автоматически не удаляются.
CI проверяет анализатор перед тестами, а workflows сохраняют JSON-отчёты даже
при ошибке. Публикация зависит от успешного завершения сборок.

Используется диагностический custom scan `MpCmdRun -Scan -ScanType 3
-File <файл> -DisableRemediation -ReturnHR`. По
[документации Microsoft](https://learn.microsoft.com/en-us/defender-endpoint/command-line-arguments-microsoft-defender-antivirus)
`DisableRemediation` относится только к этому сканированию: исключения
игнорируются, архивы проверяются, автоматическое исправление не выполняется,
результат выводится в консоль. Этот параметр не выключает защиту в реальном
времени; её состояние также записывается в отчёт. Скрипт не меняет настройки
защиты, исключения или карантин.

## Проверка классификации Microsoft

[Microsoft Security Intelligence](https://www.microsoft.com/en-us/wdsi/filesubmission)
принимает конкретный файл с предполагаемым ложным срабатыванием. Для обращения
нужны имя обнаружения, версия баз и описание поведения программы. Передача
файла и описания выполняется только после отдельного согласия владельца проекта.
Положительный ответ Microsoft необходимо подтвердить повторным сканированием
после обновления баз. Один успешный скан не гарантирует отсутствие обнаружений
в последующих версиях баз или других антивирусах.

Ключ Ed25519 для метаданных автообновления не является сертификатом Windows
Authenticode и не подтверждает издателя EXE для Windows.
