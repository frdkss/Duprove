# Установка и сборка пакетов

Выбор пользователя от 2026-10-14: Linux распространяется как `tar.gz`; добавляется
установщик macOS. Для macOS выбран `.pkg`, чтобы сведения о данных показывались
в самом мастере установки. Windows сохраняет NSIS. AppImage/deb и dmg/zip больше
не являются основными целями упаковки.

Windows NSIS устанавливает приложение для текущего пользователя. Ярлык на рабочем
столе по умолчанию не создаётся (`createDesktopShortcut: false`); приложение
доступно через меню «Пуск». Создание файлов самого приложения и профиля требуется
для установки и сохранения результатов. Публикация Windows EXE по-прежнему зависит
от успешной проверки анализатора и установщика в Defender.

## Windows

Windows-пакет — `Duprove-<версия>-win-<архитектура>.exe`, мастер NSIS на русском языке.
При обычном запуске показываются сведения о данных, затем полный текст GNU GPL v3
из корневого `LICENSE`. Продолжение со страницы лицензии требует галочки
«Я принимаю условия GNU GPL v3.». Принятие лицензии не изменяет настройку статистики.
Текст лицензии не изменён; его копия устанавливается как `LICENSE.txt` рядом с
`Duprove.exe`.

В мастере доступен выбор папки установки. Используется установка для текущего
пользователя без запроса повышения прав; выбранная папка должна быть доступна
этому пользователю для записи. NSIS может добавить подпапку `Duprove` к выбранному
каталогу. В меню «Пуск» создаётся ярлык приложения.

В каталоге программы создаётся `Uninstall Duprove.exe`, а в списке установленных
приложений Windows — запись `Duprove <версия>` с командой удаления. Деинсталлятор
имеет собственный мастер. Обычное удаление сохраняет отдельный пользовательский
профиль с настройками и отчётами.

При штатном автоматическом обновлении (`--updated`, `/S`) интерактивные страницы
не показываются; существующая папка и пользовательские настройки сохраняются.

Сборка на Windows: `npm run package`. Новый пакет можно выпускать только после
успешной проверки Defender. Наличие старого EXE в `release/` не означает успешную
сборку установщика с текущими настройками.

Первая проверка 2026-10-20: конфигурация принята electron-builder, четыре проверки
упаковки прошли. Изолированная проверка препроцессором NSIS подтвердила полный
`LICENSE`, `LicenseForceSelection checkbox`, страницу выбора папки и страницы
деинсталлятора. Полная команда `npm run package` остановилась в `beforePack` с
`WINDOWS_DEFENDER_CHECK_FAILED`: анализатор по-прежнему обнаруживается как
`Trojan:Win64/Tedy.PGL!MTB`. Новый EXE не создан, установка и удаление текущей
сборки через графический мастер не проверялись.

При повторной проверке того же анализатора Defender вернул `clean`; штатная
проверка упаковки отдельно прошла. Локальный установщик успешно собран:
`release/windows-installer/Duprove-1.0.0-win-x64.exe`. Сам установщик также прошёл
Defender. Отчёты — `release/windows-installer/defender-report.json`. В пакет вошли
актуальная сборка, анализатор и неизменённый `LICENSE.txt`; мастер NSIS с лицензией
и деинсталлятором скомпилирован. Интерактивная установка и удаление не выполнялись.

## Linux

Распакуйте весь `Duprove-<версия>-linux-<архитектура>.tar.gz` в отдельный каталог
и выполните из него `bash install.sh`. Установщик сначала выводит полный текст
`resources/statistics-notice.txt`, затем ждёт Enter для продолжения установки.
Ctrl+C отменяет её. Это шаг продолжения установки, без отдельной галочки согласия.
`bash install.sh --non-interactive` не ждёт ввода, но тоже выводит уведомление до
копирования файлов. Просто распаковка tar.gz не запускает установку.

Установка выполняется без root и sudo, для текущего пользователя:

- файлы приложения: `$XDG_DATA_HOME/duprove`, по умолчанию `~/.local/share/duprove`;
- команда запуска: `~/.local/bin/duprove`;
- ярлык меню: `$XDG_DATA_HOME/applications/duprove.desktop`.

Повторный запуск установщика обновляет собственный каталог приложения. Закройте
программу перед обновлением. Непомеченные каталоги, чужая команда `duprove` и
чужой ярлык не перезаписываются. Настройки и отчёты Electron остаются отдельно;
установщик их не читает и не меняет, включая ранее сохранённый отказ от статистики.
Для нового профиля настройка включена по умолчанию согласно последнему решению.

Требуются Bash, обычные GNU-утилиты, glibc и графические библиотеки Electron.
Архив не является универсальной статической сборкой для всех Linux: совместимость
с glibc/libstdc++ зависит от системы сборки. CI использует Ubuntu 22.04; локальный
архив этой сессии собран и проверен в Ubuntu 26.04 через WSL2. Его анализатор требует
версии символов GLIBC 2.38, GLIBCXX 3.4.32 и CXXABI 1.3.15; совместимость этого
конкретного бинарника с более старыми дистрибутивами не заявлена. Alpine/musl не
заявлены. Установщик не отключает sandbox Chromium и не меняет системные политики
пространств имён. Потребность в такой политике зависит от дистрибутива.

Минимальная серверная установка Linux может не содержать библиотек Electron:
GTK 3, NSS/NSPR, ALSA, GBM и X11. Например, в использованной Ubuntu WSL отсутствовали
`libnss3` (с зависимостью `libnspr4`) и `libasound2t64`. Установщик не устанавливает
системные пакеты с повышением прав; эти зависимости должны быть доступны в ОС.

## macOS

Для обеих архитектур создаются два формата: `.pkg` и `.dmg`.
Apple Silicon: `Duprove-<версия>-mac-arm64.dmg`; Intel: `Duprove-<версия>-mac-x64.dmg`.
В DMG находятся `Duprove.app`, ссылка `Applications` для перетаскивания приложения
и файл «О данных.txt» с общим уведомлением. Открытие DMG не показывает отдельную
страницу согласия; текст открывается пользователем. Автоматическая информационная
страница установки относится к PKG. Профиль и сохранённый отказ при копировании
приложения не меняются.

Пакеты `Duprove-<версия>-mac-x64.pkg` и `Duprove-<версия>-mac-arm64.pkg` создаются
отдельно для Intel и Apple Silicon. Страница Introduction содержит уведомление
о локальном анализе, отправляемых данных и включённой по умолчанию настройке.
Это информационная страница, а не дополнительное подтверждение сбора данных.
Текст генерируется из того же `docs/statistics-notice.txt`, который входит в пакет.

Используется стандартный Installer macOS: `/Applications` либо `~/Applications`
при выборе установки для текущего пользователя. Установочные скрипты, изменение
настроек статистики и снятие quarantine не добавлены. Перед обновлением Installer
просит закрыть Duprove. В Info.plist добавлены описания назначения доступа к
пользовательским папкам, внешним и сетевым томам; разрешения ОС не обходятся.

Подпись Developer ID и notarization в этой задаче не настроены: сертификаты и
учётные данные не предоставлены. Конфигурация без подписи предназначена для
проверки сборки; штатную доставку через Gatekeeper она не подтверждает.

## Команды сборки и проверки

Нужны Node.js 24, CMake 3.24+, C++17-компилятор и зависимости проекта (`npm ci`).
Для macOS нужны SDK и инструменты `pkgbuild`/`productbuild`; сборка выполняется на Mac.
Используйте отдельную рабочую копию для каждой ОС/архитектуры, поскольку CMake cache
и `node_modules` привязаны к платформе.

```sh
# На Linux:
npm run package:linux
python3 tests/test_linux_installer.py
python3 tests/test_linux_archive.py
# В графическом сеансе либо под xvfb-run:
node tests/packaged-startup.cjs release/linux-unpacked/duprove

# На macOS, отдельно на Intel и Apple Silicon:
npm run package:mac
python3 tests/test_macos_package.py
node tests/packaged-startup.cjs release/mac*/Duprove.app/Contents/MacOS/Duprove

# На любой поддерживаемой ОС, для текущей архитектуры:
npm run package
ctest --test-dir build/native -C Release --output-on-failure
npm run test:drives
```

Упаковка сначала собирает C++-анализатор и интерфейс. `beforePack` проверяет формат
и CPU native-бинарника: PE/ELF/Mach-O и x64/arm64 должны совпадать с пакетом.
Windows-анализатор нельзя случайно положить в Linux/macOS-пакет. Все команды
используют `--publish never`.

CI `.github/workflows/checks.yml` включает Windows, Ubuntu 22.04, macOS Intel и
Apple Silicon; сохраняет установщики как artifacts. На Linux он проверяет реальный
tar.gz во временном профиле, на macOS — ресурсы PKG и запуск вложенного анализатора.
Проверка PKG через `pkgutil --expand-full` не устанавливает приложение в `/Applications`.
Проверка DMG монтирует образ только для чтения и проверяет приложение, ссылку
Applications, уведомление, архитектуру Electron/анализатора и список томов.
После проверки образ отсоединяется. Оба формата сохраняются в Actions artifacts;
автоматическая публикация в GitHub Releases по-прежнему не включена.
Workflow подготовлен локально; его наличие не является результатом удалённого запуска.

Опции `.pkg` сверены с установленным `app-builder-lib` и
[документацией electron-builder](https://www.electron.build/pkg/);
метки macOS runners — с [документацией GitHub](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).
