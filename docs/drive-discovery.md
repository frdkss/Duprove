# Обнаружение накопителей Linux и macOS

Локальная операция `duprove-analyzer --drives` возвращает смонтированные тома,
их точки монтирования, ёмкость и доступное место. Несмонтированные устройства,
неразмеченные диски и заблокированные зашифрованные разделы не обнаруживаются
этим API. Оно не обходит файлы и не отправляет статистику.

## Linux

Источник — `/proc/self/mountinfo` текущего процесса. Парсер учитывает необязательные
поля, разделитель `-`, корень файловой системы и экранирование пробела, табуляции,
перевода строки и обратного слеша. Экранирование декодируется один раз.
Прежнее чтение `/proc/self/mounts` и последовательная замена escape-последовательностей
не обеспечивали эти свойства.

Выдаются корневой том, локальные файловые системы с источником `/dev/*`, ZFS,
NFS/NFS4, CIFS/SMB3, пользовательские FUSE-тома, а также 9p/drvfs в WSL.
Одинаковый корень одной файловой системы, смонтированный повторно, показывается один
раз; разные Btrfs subvolume roots остаются отдельными. При наложенных монтированиях
по одному пути выбирается верхнее. Системные виртуальные FS, Snap/squashfs,
служебные FUSE-порталы и системные пути исключаются. В `/run` сделано точное
исключение для `/run/media`: выбранные там накопители разрешены также локальному
анализатору. Обычные папки, которые не являются точками монтирования, не добавляются.

Ёмкость читается через `std::filesystem::space`; исчезнувшие или недоступные точки
пропускаются. Медленный/зависший сетевой сервер может задержать системный запрос
места; внешний Electron API имеет общий тайм-аут 15 секунд. Изолированных тайм-аутов
для каждого сетевого тома пока нет. Физические USB-устройства и реальные NFS/SMB
серверы в этой сессии не проверялись.

Формат mountinfo сверялся с
[документацией ядра Linux](https://docs.kernel.org/filesystems/proc.html).

## macOS

Источник — `getmntinfo(..., MNT_NOWAIT)` и структуры `statfs` ОС. Список больше не
строится обходом папок `/Volumes` и не зависит от имени `Macintosh HD`. Это устраняет
ложные диски из обычных каталогов и исключение внешнего диска с таким именем.

Используются фактические точки монтирования и идентификаторы файловых систем.
Системный корень показывается один раз. Служебные APFS-тома в `/System/Volumes`,
`devfs`, `autofs` и тома с флагом `MNT_DONTBROWSE` пропускаются. Внешние и сетевые
тома могут находиться не только в `/Volumes`. Ёмкость берётся из снимка `statfs`;
`MNT_NOWAIT` избегает синхронного обновления статистики каждого сетевого тома,
поэтому свободное место может быть немного устаревшим.

API и поля сверены с
[описанием getmntinfo Apple](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/getmntinfo.3.html)
и [заголовком mount.h XNU](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/mount.h).
Локального Mac нет: реальный вызов API, TCC и поведение накопителей на macOS в этой
сессии не запускались. Подготовлены отдельные CI-проверки Intel/Apple Silicon.

## Проверки

- `mount-discovery` в CTest: искусственные записи Linux и macOS, NFS4, FUSE,
  WSL, ZFS, разные subvolumes, алиасы, служебные тома и escape-последовательности.
- `tests/test_drives.py`: read-only вызов настоящего бинарника; реальные, уникальные
  точки монтирования и допустимые размеры без записи локальных путей в лог.
- `tests/test_linux_mount_namespace.py`: Linux bind mount в изолированном mount
  namespace, том под `/run/media`, имя с пробелом и буквальным `\040`, исключение
  обычного соседнего каталога. Монтирования основной системы не меняются.

Фактические результаты конкретных запусков записаны в [verification.md](verification.md).
