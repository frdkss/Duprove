# Duprove

Школьный проект ученика 10 класса, Сивакова Фёдора Юрьевича
Программа для обнаружения дубликатов файлов в ОС, с возможностью архивации, слияния, удаления и ручной проверки подозрительных файлов.

## Сайт

Одностраничный сайт на TypeScript, React 19.3, Vite 8 и Tailwind CSS 4. Анимация заголовка использует GSAP, ScrollTrigger приостанавливает её вне экрана. Motion отвечает за переключение скриншотов, Lucide React — за SVG-иконки.

### Локальный запуск

Нужен Node.js 24 и npm.

```sh
npm ci
npm run dev
```

Проверка и сборка:

```sh
npm test
npm run build
npm run preview
```

Браузерные проверки используют тестовые ответы GitHub и запускаются отдельно:

```sh
npx playwright install chromium
npm run test:browser
```

`npm run format` форматирует исходники, `npm run format:check` проверяет форматирование.

После `npm run dev` откройте http://127.0.0.1:5173/. Порт закреплён за Vite; если он занят, сервер явно сообщит об этом. Live Server на порту 5500 не компилирует TSX: при открытии исходного `index.html` показана подсказка со ссылкой на Vite. Результат сборки находится в `dist`; для просмотра готовой сборки используйте `npm run preview`.

### Структура

- `src/components` — отдельная папка, TSX-файл и CSS для каждого компонента.
- `src/hooks` — состояние и жизненный цикл анимаций, слайдера и загрузки релизов.
- `src/animations` — таймлайн печати и удаления дубликата.
- `src/api` — запросы к GitHub.
- `src/lib` — отдельный файл для каждой функции обработки данных.
- `src/config` — репозиторий, список скриншотов и вопросы опроса.
- `src/styles/global.css` — общие стили, цвета, Tailwind и скроллбар.
- `tests` — проверки определения ОС, файлов сборки и получения релизов.

Шапка импортируется из `src/components/Header/Header.tsx`.

### Оформление

Цветовая палитра задана в `src/styles/global.css`: почти белый фон, светлые холодные зелёные поверхности и тёмный серо-зелёный текст. Шрифт берётся из системы: `-apple-system` / `BlinkMacSystemFont` на Apple, затем установленные системные аналоги. Файлы шрифтов Apple не включены в проект и не загружаются с внешних серверов.

### Релизы

По умолчанию сайт читает публичные релизы `frdkss/Duprove` через GitHub REST API при открытии страницы. Для другого репозитория скопируйте `.env.example` в `.env.local` и измените `VITE_GITHUB_REPOSITORY` перед сборкой. Токен доступа не нужен; секреты в переменные `VITE_` добавлять нельзя — они попадают в клиентскую сборку.

Актуальная версия определяется через `/releases/latest`, предыдущая — по дате публикации среди более ранних стабильных релизов. Черновики и предварительные версии пропускаются. Ссылки берутся из `browser_download_url` опубликованных assets. Если версии или файлы отсутствуют, страница сообщает об этом. При недоступности API остаётся ссылка на GitHub и кнопка повторного запроса.

Для однозначного выбора ОС используйте имена вида `duprove_windows_x64.exe`, `duprove_windows_ARM64.zip`, `duprove_linux_x64.tar.gz`, `duprove_linux_ARM64.AppImage`. Распознаются также MSI, MSIX, DEB и RPM. ZIP и 7Z без указания ОС не показываются как установочные сборки. Контрольные суммы, подписи, исходники и отладочные архивы исключаются. ARM64, x64 и x86 отображаются по фактически опубликованным именам файлов.

ОС определяется по данным браузера; выбор можно изменить вручную. Android, iOS и ChromeOS не считаются поддерживаемыми настольными ОС. Для macOS выводится сообщение, что версия не разработана и не планируется.

### Опрос

Вместо списка изменений размещён блок «Анонимный опрос». Вопросы задаются массивом `surveyQuestions` в `src/config/survey.ts`; сейчас массив пуст и сайт показывает «Вопросы появятся позже».

Каждый вопрос содержит уникальный `id`, текст `title` и массив `options`. У варианта ответа есть уникальный в пределах вопроса `id` и текст `label`. Количество вопросов и вариантов не ограничено интерфейсом.

Вопросы показываются по одному. Посетитель выбирает один вариант или вводит свой ответ; ввод своего ответа снимает выбор варианта. Пробелы не считаются ответом. Кнопка «Назад» возвращает к предыдущему вопросу с сохранением введённого ответа. Ответы существуют только в памяти открытой страницы и сбрасываются после обновления.

Сервис сбора ответов пока не подключён. Интерфейс явно сообщает об этом и не имитирует отправку. Тестовые вопросы используются только в браузерных тестах.

### Скриншоты

Положите изображения в `public/screenshots`, затем заполните массив в `src/config/screenshots.ts`:

```ts
export const screenshots: Screenshot[] = [
  { src: 'screenshots/search.webp', alt: 'Окно поиска дубликатов' },
  { src: 'screenshots/results.webp', alt: 'Результаты поиска дубликатов' },
]
```

Пути указываются без начального `/`. При отсутствии изображений видна заглушка; одно изображение показывается без управления; несколько переключаются каждые 5 секунд. Предусмотрены ручное переключение и пауза. Автослайд останавливается при наведении, фокусе, скрытии вкладки и системной настройке уменьшения движения.

### Анимация названия

Основное слово печатается один раз за 0,9 секунды, затем следует пауза 0,8 секунды. Дубликат печатается за 1,05 секунды и через 0,65 секунды выделяется с подсказкой «найден дубликат». Выделение держится 1,2 секунды, затем дубликат плавно исчезает за 0,35 секунды. После паузы 2,6 секунды начинается новый ввод только дубликата. Один повтор занимает 5,85 секунды. Все тайминги находятся в `src/config/animation.ts`.

Анимацию можно приостановить кнопкой рядом с названием. При `prefers-reduced-motion` отображается неподвижное название.

### GitHub Pages

В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**. Workflow `.github/workflows/pages.yml` собирает и публикует сайт при отправке изменений в `main` или `master`; его также можно запустить вручную через **Actions → Publish GitHub Pages → Run workflow** для выбранной ветки.

Vite использует относительный `base`, поэтому сборка работает и в подпапке `/Duprove/`, и в корне домена. Релизы запрашиваются при открытии страницы: публикация новой версии приложения не требует пересборки сайта.
