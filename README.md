# Duprove
Школьный проект ученика 10 класса, Сивакова Фёдора Юрьевича
Программа для обнаружения дубликатов файлов в ОС, с возможностью архивации, слияния, удаления и ручной проверки подозрительных файлов.

Текущее состояние — локальный анализ итерации 1 только для чтения,
контракт статистики и управление согласием на её отправку. Архивация, слияние, удаление и перемещение файлов в эту итерацию
не входят. UI позволяет выбрать накопители, просмотреть их объём, выбрать режим
нагрузки и светлую/тёмную тему, открыть настройки и справку. Доступны запуск, пауза,
остановка и ручное продолжение после перезапуска, прогресс и диаграммы по дискам,
дополнительная проверка содержания. Во время задания крестик скрывает окно в трей.
Недоступные параметры настроек отключены. Логотип — `public/logo.svg`.
Из него автоматически создаются `public/logo.ico` и `public/logo.png` для окна,
панели задач и упакованного приложения. Генерация выполняется при сборке,
запуске разработки и через `service.bat`; отдельно — `npm run icons`.

При ширине до 1280 px интерфейс масштабируется через `rem`. В более широких окнах размеры текста, кнопок и бокового меню сохраняются, увеличивается рабочая область;
минимальный размер окна — 640×480. Карточка диска одновременно переключает галочку
и отображаемый обзор. Стрелки переключают только выбранные диски в порядке списка,
не меняя галочки. У первого диска нет стрелки назад, у последнего — вперёд;
при выборе одного диска обе стрелки скрыты.
«Выбрать всё» находится над списком; списки дисков и режимов плавно раскрываются.
Список накопителей остаётся только в боковом меню. При раскрытии режимов
центральная область целиком отведена обзору выбранного диска.
«Помощь» открывает `https://duprove.site/#instrucitons` в системном браузере.

В Windows можно запустить **`service.bat`**: пункт **1** устанавливает зависимости,
**2** собирает и запускает с логом, **3** — без сервисных логов.
Меню и дополнительные команды описаны в [service/README.md](service/README.md).

«Настройки → Дополнительно → Отправлять анонимную статистику» — отправка статистики
для школьного проекта. По умолчанию включено для нового профиля; ранее сохранённый
отказ сохраняется. Окон при запуске и подтверждений
при отключении нет. Выбор сохраняется на устройстве; старые отчёты после отзыва
остаются локально и после повторного согласия не отправляются. Сетевой транспорт
пока не подключён. Установщик Windows показывает информацию о данных без отдельного
подтверждения согласия. Подробности и границы реализации: [docs/consent.md](docs/consent.md).

Пакеты: Windows — NSIS, Linux — `tar.gz` с `install.sh`, macOS — `.pkg` и `.dmg` для Intel
и Apple Silicon. В Linux информация о данных показывается до копирования файлов,
в macOS PKG — на первой странице установщика; в DMG рядом с приложением лежит
файл «О данных.txt». Сборка: `npm run package` на целевой ОС;
подробности — [docs/installation.md](docs/installation.md).
Обнаружение смонтированных томов и ограничения проверки Linux/macOS:
[docs/drive-discovery.md](docs/drive-discovery.md).

Для разработки нужны Node.js 24, Python 3.12+, CMake 3.24+, C++17-компилятор
(Windows: Visual Studio Build Tools с Desktop development with C++; Linux: GCC/Clang).
Первичная установка зависимостей требует интернета, запуск установленного приложения — нет.

```sh
npm ci
python -m venv .venv
```

Активировать окружение: Windows PowerShell — `.venv/Scripts/Activate.ps1`,
Linux — `source .venv/bin/activate`. Затем на обеих платформах:

```sh
python -m pip install -r backend/requirements.txt
npm run native:configure
npm run native:build
npm run build
npm test
npm run test:backend
npm run test:native
npm run test:statistics
npm run test:traversal
npm run test:comparison
npm run test:content
npm run test:resume
npm run test:runtime
npm run test:desktop
ctest --test-dir build/native -C Release --output-on-failure
npm start
```

`npm run dev` запускает Vite и Electron для разработки. C++ нужно предварительно
собрать командами выше. `test:native` использует временные искусственные файлы,
а не накопители пользователя. CI настроен на сборку и проверки Windows, Linux и macOS
(Intel/Apple Silicon).
Наличие CI-конфигурации само по себе не подтверждает прохождение удалённого запуска.
`npm run test:ui` проверяет Electron/preload/React на искусственных накопителях
и сохраняет снимки экранов в `.verification/ui-*.png`; на Linux нужен графический сеанс
или Xvfb. Результаты локальной проверки: [docs/verification.md](docs/verification.md).
`test:resume` проверяет сохранение хешей после прерывания и актуальность кэша,
`test:runtime` — границы обработки содержания в режимах нагрузки,
`test:desktop` — скрытие окна в трей и завершение приложения; ему также нужен
графический сеанс. Замеры ресурсов: `python tests/benchmark_analysis.py`.
