# Duprove

Школьный проект ученика 10 класса, Сивакова Фёдора Юрьевича
Программа для обнаружения дубликатов файлов в ОС, с возможностью архивации, слияния, удаления и ручной проверки подозрительных файлов.

## Сайт

Одностраничный сайт на TypeScript, React 19.3, Vite 8 и Tailwind CSS 4. Анимация заголовка использует GSAP, ScrollTrigger приостанавливает её вне экрана. Motion отвечает за переключение скриншотов, Lucide React — за SVG-иконки.

### Локальный запуск

Нужен Node.js 24 и npm.

```sh
npm ci
npm run dev
```

Проверка и сборка:

```sh
npm test
npm run build
npm run preview
```

Браузерные проверки используют тестовые ответы GitHub и запускаются отдельно:

```sh
npx playwright install chromium
npm run test:browser
```

`npm run format` форматирует исходники, `npm run format:check` проверяет форматирование.

После `npm run dev` откройте http://127.0.0.1:5173/. Порт закреплён за Vite; если он занят, сервер явно сообщит об этом. Live Server на порту 5500 не компилирует TSX: при открытии исходного `index.html` показана подсказка со ссылкой на Vite. Результат сборки находится в `dist`; для просмотра готовой сборки используйте `npm run preview`.

### Структура

- `src/components` — отдельная папка, TSX-файл и CSS для каждого компонента.
- `src/hooks` — состояние и жизненный цикл анимаций, слайдера и загрузки релизов.
- `src/animations` — таймлайн печати и удаления дубликата.
- `src/api` — запросы к GitHub.
- `src/lib` — отдельный файл для каждой функции обработки данных.
- `src/config` — репозиторий и список скриншотов.
- `src/styles/global.css` — общие стили, цвета, Tailwind и скроллбар.
- `tests` — проверки определения ОС, файлов сборки и получения релизов.

Шапка импортируется из `src/components/Header/Header.tsx`.

### Оформление

Цветовая палитра задана в `src/styles/global.css`: почти белый фон, светлые холодные зелёные поверхности и тёмный серо-зелёный текст. Шрифт берётся из системы: `-apple-system` / `BlinkMacSystemFont` на Apple, затем установленные системные аналоги. Файлы шрифтов Apple не включены в проект и не загружаются с внешних серверов.

### Релизы

По умолчанию сайт читает публичные релизы `frdkss/Duprove` через GitHub REST API при открытии страницы. Для другого репозитория скопируйте `.env.example` в `.env.local` и измените `VITE_GITHUB_REPOSITORY` перед сборкой. Токен доступа не нужен; секреты в переменные `VITE_` добавлять нельзя — они попадают в клиентскую сборку.

Актуальная версия определяется через `/releases/latest`, предыдущая — по дате публикации среди более ранних стабильных релизов. Черновики и предварительные версии пропускаются. Ссылки берутся из `browser_download_url` опубликованных assets. Если версии или файлы отсутствуют, страница сообщает об этом. При недоступности API остаётся ссылка на GitHub и кнопка повторного запроса.

Для однозначного выбора ОС используйте имена вида `duprove_windows_x64.exe`, `duprove_windows_ARM64.zip`, `duprove_linux_x64.tar.gz`, `duprove_linux_ARM64.AppImage`. Распознаются также MSI, MSIX, DEB, RPM, DMG и PKG. Для macOS Intel используйте `macos-64bit-x86_64`, для macOS ARM — `macos-64bit-arm64` в имени файла. ZIP и 7Z без указания ОС, а также файлы macOS без указания архитектуры не показываются как установочные сборки. Контрольные суммы, подписи, исходники и отладочные архивы исключаются.

ОС определяется по данным браузера; выбор можно изменить вручную. Android, iOS и ChromeOS не считаются поддерживаемыми настольными ОС. macOS разделена на Intel и ARM. Архитектура определяется через User-Agent Client Hints, а при их недоступности — по доступному имени GPU (Apple M-серии, Intel, AMD или NVIDIA). Строки `Intel Mac` и `MacIntel` не считаются доказательством Intel: их используют и браузеры на Apple Silicon. Если браузер скрывает архитектуру и имя GPU, сайт предлагает ручной выбор. Поздний результат определения не перезаписывает ручной выбор.

### Описание релиза

Блок «Что нового» автоматически показывает `body` актуального стабильного релиза из того же ответа GitHub API, что и ссылки на установщики. Версии, описания и ссылки не зафиксированы в коде: после публикации нового актуального релиза достаточно обновить страницу.

Описание поддерживает Markdown и HTML: заголовки, абзацы, списки, ссылки, таблицы и блоки кода. `marked` разбирает Markdown, а DOMPurify очищает итоговую разметку от исполняемого HTML. При отсутствии релиза или описания показывается соответствующее сообщение. Кнопка повторного запроса обновляет обе панели.

### Инструкция на сайте

Раздел «Инструкция» автоматически загружает `instruction.md` из ветки `main` через `raw.githubusercontent.com`. Запрос начинается, когда раздел приближается к экрану, либо сразу при открытии страницы с `#instructions`. Файл Markdown загружается целиком, но в свёрнутом состоянии разбирается и отрисовывается только начало текста.

Предпросмотр ограничен по высоте и закрыт градиентом в цвет фона. Нажатие на область предпросмотра (или Enter/Space на кнопке) раскрывает полный текст с анимацией высоты. Прямая ссылка `/#instructions` и переход к разделу из навигации также раскрывают инструкцию. При `prefers-reduced-motion` раскрытие происходит без анимации. Markdown и HTML проходят ту же очистку, что и описание релиза. При ошибке доступны повторный запрос и ссылка на исходный файл.

### Скриншоты

Положите любое количество изображений в `public/screenshots`: ручной список не нужен. Vite автоматически включает PNG, JPG/JPEG, WebP, AVIF и GIF из этой папки, сортируя имена в естественном порядке (`1.png`, `2.png`, `10.png`). Изображения показываются целиком, без обрезки.

При отсутствии изображений видна заглушка; одно изображение показывается постоянно; несколько переключаются каждые 3,5 секунды по кругу. Новый скриншот плавно проявляется поверх предыдущего за 1,15 секунды; нижний слой остаётся непрозрачным до завершения перехода. Кнопок и счётчика нет, наведение не останавливает показ. При скрытой вкладке переключение приостановлено, а при системной настройке уменьшения движения остаётся первый скриншот.

В режиме разработки добавление и удаление изображений автоматически обновляет страницу. Для предпросмотра из `dist` и опубликованного сайта после добавления файлов нужна новая сборка и, при публикации, загрузка этой сборки на хостинг.

### Анимация названия

Основное слово печатается один раз за 0,9 секунды, затем следует пауза 0,8 секунды. Дубликат печатается за 1,05 секунды и через 0,65 секунды выделяется с подсказкой «найден дубликат». Выделение держится 1,2 секунды, затем дубликат плавно исчезает за 0,35 секунды. После паузы 2,6 секунды начинается новый ввод только дубликата. Один повтор занимает 5,85 секунды. Все тайминги находятся в `src/config/animation.ts`.

При `prefers-reduced-motion` отображается неподвижное название. Анимация приостанавливается вне экрана и при скрытии вкладки.

### GitHub Pages

В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**. Режим **Deploy from a branch** для исходников этого проекта не подходит: браузер не выполняет TSX, и сайт нужно сначала собрать.

Workflow `.github/workflows/pages.yml` запускается при отправке изменений в `website`, выполняет проверки и сборку, затем публикует только каталог `dist`. После push дождитесь успешного выполнения **Actions → Publish GitHub Pages**. При ручном запуске выбирайте ветку `website`.

Для публикации на `https://frdkss.github.io/Duprove/` задан `base: '/Duprove/'`. В режиме разработки используется `/`, поэтому локальный адрес остаётся http://127.0.0.1:5173/. Для другого имени репозитория или собственного домена измените `base` в `vite.config.ts`. Релизы запрашиваются при открытии страницы: публикация новой версии приложения не требует пересборки сайта.
