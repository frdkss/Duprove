# Duprove Service

Runner адаптирован из локального `F:/pyproj/nodagora/service.bat` и его `service/`.
Это меню разработки и запуска, а не системная служба Windows.
Двойной щелчок по `service.bat` открывает `DUPROVESERVICE`.
Его можно вызвать по полному пути из любого рабочего каталога.

| Пункт | Действие |
| --- | --- |
| 1 | Проверяет/устанавливает зависимости, собирает и проверяет C++ |
| 2 | Собирает C++ и интерфейс, запускает приложение с логом |
| 3 | То же без записи сервисных логов; ошибки выводятся в консоль |
| 99 | Создаёт отсутствующие папки из `service/directories.json`, сохраняет существующие файлы |
| 999 | Добавляет команды `srv`, `srvs`, `service`, `service.bat` в профиль PowerShell |
| 0 | Выход из меню |

Пункты можно вызвать напрямую: `service.bat 1`, `service.bat 2`,
`service.bat 3`, `service.bat 99`, `service.bat 999`.
После закрытия приложения меню возвращается; прямой вызов возвращает код 0
при успехе, ненулевой при ошибке. Пункт 3 скрывает обычный вывод сборки,
но показывает причину ошибки. Успех не выводится после неудачной сборки.

Пункт 1 рассчитан на Windows x64. Он использует Node.js 24 из PATH либо
portable-версию в `.tools`, Python через uv и окружение `.venv`, npm-зависимости
из `package.json`, CMake 3.24+, MSVC и Windows SDK. Архивы uv, Node и Electron
проверяются по SHA-256. Отсутствующие Build Tools устанавливаются через winget;
установщик Windows может потребовать повышение прав или перезагрузку.
Зависимости Docker, AI, Kubernetes и другие компоненты Nodagora здесь не нужны.
Первичная установка и получение CMake-зависимостей требуют сети.

Логи: `service/logs/run-*.log`, `install-*.log`, `dependencies.json`.
Они содержат диагностический вывод инструментов разработки, а не статистику
сканирования пользовательских файлов. Режим 3 не создаёт сервисные логи;
обычные служебные файлы сборки в `build/` сохраняются в обоих режимах.
Backend при запуске desktop не поднимается: на текущем этапе это отдельный
валидатор, и приложение работает локально.

Пункт 999 меняет профиль **только при его выборе**. Существующее содержимое
сохраняется, при изменении создаётся резервная копия с суффиксом `.duprove-*.bak`.
Обновляется только блок Duprove; повторная установка не добавляет второй блок.
После выбора в уже открытой родительской консоли выполните `. $PROFILE`.
Если ранее установлены одноимённые команды Nodagora, после загрузки профиля
последний загруженный блок определяет, какой runner они запускают.
Именованная команда `Start-DuproveService` также остаётся доступна.

Проверки runner:

```powershell
node --test tests/service.test.cjs
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/service-menu.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/service-e2e.ps1
```

Тест профиля работает только с временным файлом; реальный профиль не изменяется.
E2E-тест использует искусственный проект в папке с пробелами и `&`,
настоящий Electron показывает тестовое окно и закрывается после проверки видимости; проверяются коды выхода
и запись вывода дочернего процесса только в режиме с логом.

Проверено локально 2026-10-13: пункт 1 на существующем окружении
(`python: ok`, `node: ok`, `native: ok`), пункт 99 из другого рабочего каталога,
реальная сборка Duprove, 4 теста Node, тест временного профиля и E2E запуска.
Установка инструментов на чистой Windows без Node/Python/MSVC не проверялась.

Исправление запуска: `windowsHide` включён только для инструментов сборки.
Для Electron он выключен, иначе Windows скрывает основное окно приложения.
`npm run test:startup` проверяет видимость настоящего окна Duprove и загрузку React,
после чего закрывает его. Требуется предварительная `npm run build`.
